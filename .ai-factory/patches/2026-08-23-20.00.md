# Протокольные контракты Redis-уведомлений

**Дата:** 2026-08-23 20:00
**Файлы:** `src/viatradetgbot/notifications/contracts.py`, `src/viatradetgbot/notifications/redis_client.py`, `src/viatradetgbot/notifications/store.py`, `src/viatradetgbot/notifications/consumer.py`, `src/viatradetgbot/app.py`, `tests/test_notifications.py`
**Серьёзность:** medium

## Проблема

Pylance не позволял передавать `FakeRedis` в `NotificationStore`, потому что
конструктор требовал конкретный `redis.asyncio.Redis`. В тестах также были
нетипизированные `SimpleNamespace` и подмена приватного поля `_store` двойником,
не совместимым с конкретным классом.

## Корневая причина

Границы зависимостей в слое уведомлений были объявлены через реализации, а не
через используемые возможности. Поэтому тестовые двойники должны были имитировать
весь клиент Redis и класс хранилища, хотя прикладному коду нужен ограниченный набор
операций Redis Streams и delivery-хранилища. Типы `redis-py` дополнительно
наследуют обобщённый `ResponseT`, который не отражает результат асинхронных команд
в строгом Protocol-контракте.

## Решение

Добавлены узкие Protocol-контракты для настроек, Redis-команд и notification store.
`NotificationConsumer` принимает `NotificationStoreProtocol` через конструктор,
поэтому тесты используют двойник напрямую, без записи в приватное поле. Реальный
Redis подключён через `RedisNotificationClientAdapter`, который локализует
неоднозначные аннотации внешней библиотеки и предоставляет строго типизированный
контракт приложению. Тестовые настройки заменены на неизменяемую dataclass.

## Предотвращение

- Внедрять внешние сервисы через минимальный Protocol, описывающий используемые
  операции, а не через конкретный клиент.
- Для библиотек с неточными или обобщёнными аннотациями держать `cast` только в
  адаптере на границе интеграции.
- Передавать тестовые двойники через публичные точки внедрения зависимостей, не
  подменяя приватные поля.
- Проверять тесты вместе с Pyright, чтобы структурная совместимость двойников
  оставалась гарантированной.

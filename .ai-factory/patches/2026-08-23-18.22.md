# Переход с удалённого `GET /reminders/due` на Redis Stream

**Date:** 2026-08-23 18:22
**Files:** `src/viatradetgbot/app.py`, `src/viatradetgbot/integrations/backend_api.py`, `src/viatradetgbot/notifications/`, `src/viatradetgbot/config.py`, `tests/test_notifications.py`
**Severity:** high

## Problem

После удаления `GET /api/v1/internal/tgbot/reminders/due` из OpenAPI импорт
приложения завершался ошибкой `ImportError: cannot import name 'get_due'`.
Poller продолжал зависеть от удалённой модели ответа и периодически опрашивал
backend вместо ожидания уведомления.

## Root Cause

Клиентский код был переведён на polling для временного HTTP-контракта, но
получение напоминаний не было возвращено на событийный контракт после удаления
route. В обновлённом контракте backend оставляет только подтверждение доставки.

## Solution

Восстановлен consumer Redis Stream с consumer group и `XREADGROUP BLOCK` для
ожидания новых записей без polling. Сообщение подтверждается в Redis только после
отправки в Telegram и успешного вызова `ConfirmDelivery`. Дедупликационный ключ
не допускает повторной отправки при повторе подтверждения, `XAUTOCLAIM` возвращает
pending-сообщения после сбоя, а некорректные или навсегда отклонённые сообщения
переносятся в DLQ и подтверждаются.

## Prevention

- После регенерации OpenAPI запускать импорт приложения: он сразу выявляет удалённые операции.
- Для событийной доставки использовать блокирующее чтение consumer group, а не опрос backend.
- Проверять порядок `Telegram -> backend confirmation -> Redis ACK` и обработку постоянных ошибок Telegram.

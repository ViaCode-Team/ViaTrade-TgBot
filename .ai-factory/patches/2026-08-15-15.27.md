# Доверие к системному TLS-хранилищу для Backend

**Дата:** 2026-08-15 15:27
**Файлы:** `src/viatradetgbot/integrations/backend_client.py`, `tests/test_backend_tls.py`, `tests/__init__.py`
**Серьёзность:** medium

## Проблема

Привязка Telegram-аккаунта к Backend на `https://localhost:7249` завершалась до HTTP-запроса с ошибкой `CERTIFICATE_VERIFY_FAILED` для self-signed ASP.NET Core development certificate.

## Корневая причина

`httpx.AsyncClient` с параметром `verify=True` по умолчанию использует CA bundle `certifi`. В нём нет доверенного Windows ASP.NET Core development certificate, хотя тот уже установлен в системном хранилище сертификатов.

## Решение

`BackendClient` теперь передаёт в `httpx.AsyncClient` результат `ssl.create_default_context()`. Он использует системное хранилище Windows и продолжает проверять цепочку и имя сертификата. Добавлен debug-лог `[FIX]` и unit-тест, закрепляющий передачу TLS-контекста.

## Предотвращение

- Для локальных сервисов с доверенными системными сертификатами передавайте в HTTP-клиент явный системный TLS-контекст.
- Не заменяйте проверку сертификата на `verify=False`.
- Проверяйте TLS-интеграцию с реальным dev Backend после изменения HTTP-клиента.

# Устранение исключений Ruff через адаптацию API

**Дата:** 2026-08-23 20:35
**Файлы:** `pyproject.toml`, `src/viatradetgbot/notifications/contracts.py`, `src/viatradetgbot/notifications/redis_client.py`, `src/viatradetgbot/notifications/store.py`, `tests/test_notifications.py`, `src/viatradetgbot/scripts/generate_backend_api.py`
**Серьёзность:** low

## Проблема

В конфигурации Ruff были исключения `A002`, `PLR0913` и `S603`, добавленные при
переносе локальных `# noqa`. Пользователь потребовал исправлять предупреждения в
коде, а не отключать их.

## Корневая причина

Protocol и адаптер повторяли низкоуровневые сигнатуры Redis: параметр `id`
перекрывал встроенную функцию Python, а `XAUTOCLAIM` требовал шесть аргументов.
Скрипт генерации запускал установленный CLI через `subprocess`, хотя библиотека
предоставляет Python API для той же операции.

## Решение

Параметр Redis `id` заменён в прикладном контракте на `start_id`. Параметры
claim-сценария собраны в неизменяемый `StreamClaimRequest`. Вызов Redis остаётся
изолированным в адаптере. Генератор использует `openapi_python_client.Config` и
`generate` напрямую; ошибки генератора преобразуются в явное доменное исключение.
В `per-file-ignores` сохранён только `PT009` для `tests/**/*.py`.

## Предотвращение

- Не переносить локальное подавление линтера в конфигурацию до оценки возможности
  выразить предметный контракт.
- Скрывать сигнатуры внешних API за адаптерами и объектами запросов.
- Предпочитать поддерживаемый библиотечный Python API запуску CLI через subprocess.
